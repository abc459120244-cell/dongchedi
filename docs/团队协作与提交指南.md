# 团队协作与提交指南（每人都有 Git 提交记录）

> 目标：远程仓库里能看到**每位成员自己的提交**，并且每个人的提交都对应真实、可运行的功能改动。
> ⚠️ 请不要用别人的账号代提交，也不要伪造他人身份的提交 —— 那属于学术不诚信，一旦被查会直接影响成绩。

---

## 一、每个人先做一次环境准备（5 分钟）

### 1. 配置自己的 Git 身份（**邮箱必须与你 GitHub/Gitee 账号一致**，否则贡献图不会统计你）

```bash
git config --global user.name  "张三"
git config --global user.email "zhangsan@example.com"     # 必须是 GitHub 账号绑定的邮箱
git config --global core.quotepath false
git config --global i18n.commitEncoding utf-8
git config --global i18n.logOutputEncoding utf-8
```

验证：`git config --global --list`

### 2. 克隆仓库

```bash
git clone <仓库地址>
cd dongchedi
```

## 二、分工建议（每人一个分支 + 一到两个可独立完成的功能）

下面的任务都**互相不冲突**（改的文件基本不重叠），每人做完就能独立提交、独立验证。

| 成员 | 任务 | 主要文件 | 验收方式 |
| --- | --- | --- | --- |
| A | 买家端「车型对比」增加导出对比结果为文本/图片的按钮 | `static/js/app.js`、`static/css/app.css` | 勾选 2 款车 → 对比弹窗出现「导出」按钮并可用 |
| B | 商家端订单支持按车型名称搜索 + 导出 CSV | `static/merchant.html`、`static/js/merchant.js` | 输入车型名能过滤订单；导出的 CSV 能打开 |

> 也可以自行选题，只要满足：**能独立验证 + 改动落在少量文件上 + 至少一次有意义的提交**。

## 三、标准提交流程（以任务 A 为例）

```bash
# 1. 从最新 main 拉取，创建自己的功能分支（分支名用自己名字拼音 + 功能）
git checkout main
git pull
git checkout -b feature/zhangsan-export-compare

# 2. 开发……开发过程中可以多次提交
git add src/main/resources/static/js/app.js
git commit -m "feat: 车型对比支持导出为文本" -m "- 对比弹窗新增导出按钮，点击后生成格式化文本并复制到剪贴板"

# 3. 本地自测（务必跑一遍测试 + 手动点一遍页面）
mvn test

# 4. 推送自己的分支
git push -u origin feature/zhangsan-export-compare

# 5. 在平台上发起 Pull Request / 合并请求，由组长 Review 后合并到 main
```

### 提交信息规范

```
<类型>: <一句话说明>

- 变更点 1
- 变更点 2
```

类型：`feat` 新功能 / `fix` 修复 / `docs` 文档 / `style` 样式 / `refactor` 重构 / `test` 测试 / `chore` 构建配置。

## 四、怎么确认自己的提交被统计

```bash
git log --author="你的名字" --oneline        # 查看自己的提交
git shortlog -sne                            # 按作者统计提交次数（贴到验收报告里很有用）
```

在 GitHub 仓库页面 → `Insights` → `Contributors` 可以看到每人提交数与提交日历；仓库首页右侧 `Contributors` 也会列出成员。

> 如果贡献图里没有你：99% 是因为提交邮箱与 GitHub 账号邮箱不一致，改正邮箱后重新提交（或让组长用 `git log` 截图作为补充证明）。

## 六、验收演示脚本（建议照着念，3~5 分钟）

1. **展示数据库**（1 分钟）
   - 打开商家端 → 新增一个车源 → 切到买家端刷新，列表里出现了这台车 → 说明「前端写入 → 后端处理 → 数据库落库 → 前端读取」全链路通了。
   - 命令行查库佐证：`select id,name,brand,price from car order by id desc limit 3;`
2. **展示多端互动**（1 分钟）
   - 电脑开买家端，手机开商家端；买家点「预约」提交订单 → 手机端**不刷新**即弹出「收到新的订单」。
   - 手机上点「处理」→ 回复留言 → 电脑端买家收到「订单状态更新」提示。
3. **展示多端形态**（1 分钟）
   - 买家端 PC 与手机浏览器自适应；商家端独立入口 `/merchant.html`；两者共用一套后端与数据库。
4. **展示版本管理**（1 分钟）
   - GitHub 仓库：提交历史、分支结构、每人贡献图、PR 记录。
5. **展示部署**（1 分钟）
   - 用手机流量访问服务器地址，说明已部署到公网服务器。
