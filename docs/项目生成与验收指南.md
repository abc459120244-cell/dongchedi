# 车帝选车项目生成与验收指南

本文档说明如何从空项目生成「基于 Spring Boot 的汽车筛选与推荐系统」，包括架构设计、数据库、
买家端、商家端、管理端、实时消息、图片上传、测试、Git 提交和服务器部署。既可作为项目复现教程，
也可作为答辩或继续开发时的检查清单。

## 一、项目目标

最终系统需要满足以下课程要求：

1. 前端、后端和数据库完整打通。
2. 至少包含买家端、商家端和管理端三个入口。
3. 前端新增、修改、删除数据后，后端完成业务处理，最终更新数据库。
4. 买家下单后，对应商家通过 SSE 实时收到订单；商家处理后买家也能实时收到状态。
5. 提供用户登录、角色权限、车源管理、订单管理、评价、收藏和图片上传。
6. GitHub 中包含按功能拆分的提交、功能分支、合并记录和版本回滚演练。
7. 可通过 Docker、MySQL、Nginx 部署到云服务器。

## 二、最终架构

```text
浏览器
├── 买家端 /index.html
├── 商家端 /merchant.html
└── 管理端 /admin.html
        │
        ├── REST API /api/**
        └── SSE /api/notifications/stream
                    │
             Spring Boot 3.5
                    │
        Spring MVC + Validation
        Service 业务层
        Spring Data JPA
                    │
        H2 文件库（本地）
        MySQL 8（服务器）
```

核心原则：

- 控制器只负责接收参数、读取登录用户和返回结果。
- 权限、事务、数据校验和审计日志放在服务层。
- 所有业务数据都通过 JPA 持久化，不使用内存集合保存正式数据。
- 多端页面共用一套后端和数据库。
- 实时消息采用 SSE，消息同时落库，断线重连后仍可查看。

## 五、后端分层与目录

建议使用以下结构：

```text
src/main/java/com/dongchedi/car
├── config          # 数据初始化、MVC、上传目录、密码编码器
├── controller      # 买家、商家、管理员、认证、订单、消息接口
├── dto             # 请求和响应对象
├── entity          # JPA 实体
├── exception       # 业务异常与统一异常响应
├── model           # 领域模型和枚举
├── repository      # 数据访问接口
│   └── jpa         # Spring Data JPA 仓库
├── security        # 登录、商家、管理员拦截器
├── service         # 核心业务、事务、审计和实时推送
└── support         # 会话键、枚举解析等工具
```

实现顺序建议：

1. `Car`、`UserAccount`、订单等领域模型。
2. `CarEntity`、`UserEntity`、`OrderEntity`、`ReviewEntity` 等数据库实体。
3. JPA Repository。
4. Service 业务逻辑。
5. Controller 接口。
6. `GlobalExceptionHandler` 统一错误格式。

## 六、数据库设计

核心表如下：

| 表 | 作用 |
| --- | --- |
| `car` | 车型和商家车源 |
| `user_account` | 用户、商家、管理员及启用状态 |
| `favorite` | 用户收藏关系 |
| `car_order` | 预约试驾、询价和意向订单 |
| `notification` | 站内消息 |
| `review` | 车主评价 |
| `operation_log` | 商家和管理员操作审计 |

关键字段：

- `car.dealer_id`：车源归属商家。
- `car.photo_url`：商家上传的实拍图地址。
- `car.status`：`ON_SALE` 或 `OFF_SHELF`。
- `user_account.role`：`USER`、`MERCHANT`、`ADMIN`。
- `user_account.enabled`：账号是否允许登录。
- `car_order.car_name`：订单中的车型名称快照，车源删除后仍可查看历史。

本地使用：

```yaml
spring:
  datasource:
    url: jdbc:h2:file:./data/dongchedi;MODE=MySQL
  jpa:
    hibernate:
      ddl-auto: update
```

服务器使用：

```yaml
spring:
  datasource:
    url: jdbc:mysql://${DB_HOST:localhost}:3306/${DB_NAME:dongchedi}
    username: ${DB_USER:root}
    password: ${DB_PASSWORD:root}
```

## 七、核心业务模块

### 1. 车型筛选与分页

实现 11 个筛选维度：

- 品牌
- 级别
- 车身形式
- 能源类型
- 用车场景
- 价格
- 座位数
- 纯电续航
- 百公里油耗
- 用户评分
- 零百加速

接口入口：`GET /api/cars`。

分页必须由后端完成，前端翻页只替换车型列表，不修改整页滚动位置。

### 2. 智能推荐

推荐采用可解释加权模型：

- 预算匹配
- 场景匹配
- 能源偏好
- 市场销量
- 用户口碑
- 空间
- 能耗
- 动力性能

响应必须包含推荐理由和得分明细，接口入口：`POST /api/recommend`。

### 3. 用户认证和权限

登录流程：

```text
用户名 + 密码
  → BCrypt 校验
  → 检查 enabled
  → 销毁旧 Session
  → 写入新 Session
  → 后续请求由拦截器读取当前用户
```

权限约束：

- 普通用户可以收藏、评价、下单。
- 商家只能管理自己的车源和订单。
- 管理员可以管理全部车源和订单，并访问 `/api/admin/**`。

### 4. 多端订单和 SSE

```text
买家 POST /api/orders
  → 写入 car_order
  → 写入商家 notification
  → SSE 推送 order 和 notification
  → 商家订单列表自动刷新
  → 商家处理订单
  → 更新订单状态
  → SSE 推送买家
```

账号被禁用时：

1. 数据库 `enabled` 改为 `false`。
2. 旧 Session 在下一次请求时返回 `401`。
3. 服务端向已有 SSE 连接发送 `account-disabled`。
4. 主动结束连接，前端关闭 EventSource，避免无限重连。

### 5. 车源图片上传

接口：

- `POST /api/merchant/cars/{id}/photo`
- `DELETE /api/merchant/cars/{id}/photo`

限制：

- JPG、PNG、WebP
- 单张不超过 5MB
- 商家只能修改自己车源
- 上传文件保存在 `dongchedi.upload.dir`
- 数据库只保存 `/uploads/cars/...` 地址

删除车源时：

- 删除收藏关系
- 删除关联评价
- 数据库事务提交后再删除图片文件
- 保留订单历史快照

### 6. 管理端用户管理

页面：`/admin.html`

能力：

- 用户统计
- 用户搜索
- 启用 / 禁用账号
- 调整普通用户、商家、管理员角色
- 操作写入审计日志
- 禁止管理员修改自己的状态和角色

## 八、前端页面

### 买家端

`/index.html`：

- 筛选、排序、分页
- 智能推荐
- 2~4 款车型对比
- 收藏
- 车型详情与评价
- 预约试驾 / 询价
- 我的订单和实时消息

### 商家端

`/merchant.html`：

- 经营概览
- 车源新增、修改、上下架、删除
- 图片上传与删除
- 订单筛选、搜索、处理、CSV 导出
- 操作审计日志

### 管理端

`/admin.html`：

- 用户统计
- 用户列表
- 禁用 / 启用
- 角色调整

管理端和商家端表格使用局部横向滚动容器，避免手机页面被宽表格撑破。

## 十一、Git 开发流程

每个功能使用独立分支：

```bash
git switch main
git pull
git switch -c feature/模块名

# 开发并测试
mvn test

git add .
git commit -m "feat: 完成某功能"
git push -u origin feature/模块名

git switch main
git merge --no-ff feature/模块名 -m "merge: 合并某功能"
git push origin main
```

提交类型：

- `feat`：新增功能
- `fix`：修复问题
- `docs`：文档
- `test`：测试
- `refactor`：重构
- `chore`：构建和配置

版本回滚：

```bash
git log --oneline
git revert <错误提交>
git push origin main
```

同步校验：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-sync.ps1
```

## 十二、服务器部署

### Docker Compose

```bash
sudo bash deploy/deploy-ubuntu.sh
```

或：

```bash
docker compose -f deploy/docker-compose.yml up -d --build
```

容器：

- `dongchedi-mysql`：MySQL 8
- `dongchedi-app`：Spring Boot
- `dongchedi-nginx`：对外 80 端口

持久化：

- `mysql-data`：数据库
- `app-uploads`：车源图片

### 外网验收

1. 云服务器安全组放行 80。
2. 手机关闭 WiFi，使用 4G/5G 访问公网 IP。
3. 分别打开买家端、商家端和管理端。
4. 买家下单，确认商家端无需刷新即可弹出订单。
5. 商家上传车源图片，确认买家端可显示。
6. 重启容器，确认数据库和图片仍存在。

> 当前仓库已提供部署文件，但“部署到服务器”的最终得分仍以真实公网地址和跨网络访问结果为准。

## 十三、验收演示顺序

### 1. 前后端数据库

商家新增车源 → 买家端出现新车 → 修改价格 → 买家端价格变化 → 重启应用后仍存在。

### 2. 图片上传

商家编辑车源 → 上传实拍图 → 买家端显示 → 删除图片 → 回退矢量示意图。

### 3. 多端互动

电脑登录买家端，手机登录商家端；买家下单后商家实时收到；商家处理后买家实时收到。

### 4. 用户管理

管理员打开 `/admin.html`，禁用测试账号；该账号已有 SSE 立即断开，后续请求返回 401；
重新启用后可以正常登录。

### 5. Git 历史

展示：

- 功能分支
- `--no-ff` 合并记录
- 每个功能的独立提交
- `git revert` 回滚
- Contributors 提交日历
- 本地与远程同步校验输出
