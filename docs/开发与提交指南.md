# 开发与提交指南（单人独立完成）

> 本项目由**一人独立完成**（一人一组）。因此「远程仓库要有每个人的代码提交记录」这条要求，
> 对应的就是：**远程仓库里能看到你本人完整、连续、有意义的提交历史**。
> 本项目的做法是：每个功能都走「功能分支 → 多次提交 → `--no-ff` 合并回 main」，并额外做了版本回滚演练，
> 让提交历史本身就能证明开发过程，而不是最后一次性上传代码。

---

## 一、提交前先配置自己的 Git 身份（5 分钟）

**邮箱必须与你 GitHub / Gitee 账号绑定的邮箱一致**，否则平台不会把它算成你的提交。

```bash
git config --global user.name  "你的名字"
git config --global user.email "你的GitHub邮箱"
git config --global core.quotepath false
git config --global i18n.commitEncoding utf-8
git config --global i18n.logOutputEncoding utf-8
```

验证：`git config --global --list`

## 二、分支与提交规范

### 分支策略

| 分支 | 用途 |
| --- | --- |
| `main` | 可运行的主分支，只接受功能分支合并 |
| `feature/xxx` | 每个功能一个分支，开发完成后用 `git merge --no-ff` 合并，保留分支记录 |
| `practice/rollback-demo` | 版本回滚演练用的练习分支 |

### 提交信息

```
<类型>: <一句话说明>

- 变更点 1
- 变更点 2
```

类型：`feat` 新功能 / `fix` 修复 / `docs` 文档 / `style` 样式 / `refactor` 重构 / `test` 测试 / `chore` 构建配置。

### 标准流程

```bash
# 1. 从最新 main 拉取，创建功能分支
git checkout main && git pull
git checkout -b feature/your-feature

# 2. 开发，过程中多次提交（小步提交，信息说清楚做了什么）
git add <改动的文件>
git commit -m "feat: 完成 xxx 功能" -m "- 具体改动点"

# 3. 本地自测
mvn test

# 4. 推送分支
git push -u origin feature/your-feature

# 5. 合并回 main（个人项目可以自己合并，建议保留 --no-ff 合并记录）
git checkout main
git merge --no-ff feature/your-feature -m "merge: 合并 xxx 功能到 main"
git push origin main
```

## 三、怎么让提交历史"看起来不像补作业"

单人项目最容易踩的坑是：写完一次性 push 一个 "finish" 提交。建议做到：

1. **按功能拆分提交**：脚手架、数据层、筛选、推荐、统计、前端、登录、多端订单…… 一个功能一次提交
   （本项目就是按这个粒度拆的，可用 `git rev-list --count HEAD` 查看当前提交数）。
2. **用功能分支**：每个功能一个 `feature/*` 分支 + `--no-ff` 合并，历史里能看到分支结构。
3. **写清提交信息**：`feat: 实现汽车多条件筛选查询接口` 比 `update` 有用得多。
4. **保留一次真实的回滚**：本项目在 `main` 上故意提交过一个带缺陷的排序缓存（`perf: 为车型筛选结果增加排序缓存`），
   复现失败后用 `git revert` 回滚，并在 `practice/rollback-demo` 分支演示了 `git reset --hard` —— 详情见 [Git协作流程记录.md](Git协作流程记录.md)。
5. **提交时间分散**：功能是分几天做的，就分几天提交，不要集中在同一分钟。

## 四、核对提交记录

```bash
git log --oneline --graph --decorate        # 提交历史与分支结构
git shortlog -sne                           # 按作者统计提交次数
git log --author="你的名字" --oneline        # 只看自己的提交
git rev-list --count HEAD                   # 总提交数
```

平台侧查看：仓库首页右侧 `Contributors`、`Insights → Contributors` 的**提交日历**（绿色格子）。
交付时建议把「提交历史截图 + 提交日历截图 + `git shortlog -sne` 输出」一起放进验收材料。

> 如果贡献图里没有你的头像：几乎都是提交邮箱与账号邮箱不一致导致的，改对邮箱后重新提交即可。

## 五、提交作业前的检查清单

- [ ] `git config user.email` 与平台账号邮箱一致
- [ ] `main` 分支可运行：`mvn clean package` 通过、`mvn test` 全绿（当前 58 个测试）
- [ ] 数据库可复现：删除 `data/` 目录后重启，自动建表并导入 63 款车型
- [ ] 多端互动可演示：买家下单 → 商家端实时收到 → 商家处理 → 买家实时收到状态变更
- [ ] 项目已部署到服务器，用手机流量能访问
- [ ] 远程仓库包含：代码、README、`docs/` 文档、`deploy/` 部署文件
- [ ] 已准备好验收演示（见下一节）

## 六、验收演示脚本（建议照着念，3~5 分钟）

1. **数据库全链路**（1 分钟）
   - 商家端新增一个车源 → 切到买家端刷新，列表里出现这台车；再改价、下架，买家端同步变化。
   - 命令行查库佐证：`select id,name,brand,price,status from car order by id desc limit 3;`
   - 重启应用后数据仍在，说明不是内存数据。
2. **多端互动**（1 分钟）
   - 电脑开买家端、手机开商家端：买家点「预约」提交订单 → 手机端**不刷新**即弹出「收到新的订单」。
   - 手机上点「处理」并回复留言 → 电脑端买家实时收到「订单状态更新」。
3. **多端形态**（1 分钟）
   - 买家端与商家端两个入口共用一套后端与数据库；PC 与手机浏览器都自适应。
4. **版本管理**（1 分钟）
   - 展示仓库提交历史、分支结构、合并记录、版本回滚演练，以及提交日历。
5. **部署与外网访问**（1 分钟）
   - 用手机流量访问服务器地址，证明已部署到公网服务器。
