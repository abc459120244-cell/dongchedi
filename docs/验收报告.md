## 四、切换到真实的 Gitee / GitHub 远程仓库

### 1. 创建远程仓库

网页创建：仓库名 `dongchedi`、可见性 **公开**。

> ⚠️ 因为本地已经包含与平台自动初始化等价的 `Initial commit`，创建远程仓库时**不要再勾选**
> 「添加 README / 初始化仓库」，否则远程与本地会各自产生一条不同的初始提交，历史上会出现两条互不相干的分叉。

也可以用 API 直接创建（无需初始化）：

```bash
# GitHub
curl -H "Authorization: token <你的_TOKEN>" \
     -d '{"name":"dongchedi","private":false,"auto_init":false}' \
     https://api.github.com/user/repos

# Gitee
curl -X POST "https://gitee.com/api/v5/user/repos" \
     -d "access_token=<你的_TOKEN>&name=dongchedi&private=false&auto_init=false"
```

### 2. 切换 origin 并推送

```bash
git remote set-url origin https://gitee.com/<你的用户名>/dongchedi.git
# 如果还没有 origin：
# git remote add origin https://gitee.com/<你的用户名>/dongchedi.git

git push -u origin main
git push origin --all
```

### 3. 重新校验并对照

```powershell
powershell -ExecutionPolicy Bypass -File scripts/verify-sync.ps1
```

把输出与本报告第三节对照即可：52 个文件、14 个提交、6 个分支完全一致，
并用浏览器打开远程仓库确认文件、提交历史与分支结构一致。
